# ESP Zigbee SDK v2 bring-up

This is the first H2/C6 hardware tranche. It proves the official Espressif v2
component with the existing bmk and ESP-IDF 6.1 toolchain. The Zigbee module
currently exposes diagnostic entry points only; its production lifecycle,
endpoint, attribute, reporting, reset and event APIs are still to be built.

## Dependency and configuration

`Import ESP32.Network.Zigbee` adds `espressif/esp-zigbee-lib` **2.1.0** through
an optional ESP-IDF component manifest. A normal application does not discover,
compile or link the Zigbee component. Component Manager downloads it on the
first online build and caches it under `cmake/application/managed_components`.
The exact version is pinned in the manifest. `dependencies.lock` is generated by
ESP-IDF and is target-dependent, so this template does not commit a single
shared lock file for both H2 and C6. Offline builds require a populated
Component Manager cache.

The Zigbee import uses a separate `sdkconfig.zigbee` file and
`zigbee.partitions.csv`. H2 selects coordinator/router stack libraries; C6
selects end-device libraries. The default 4 MiB Zigbee layout retains both
1.5 MiB OTA slots and the normal `nvs`, `otadata` and LittleFS partitions. It
adds `zb_storage` as NVS and `zb_fct` as FAT data. The test passes `zb_storage`
to the SDK as its persistent storage partition. The normal board profiles and
normal application partitions are unaffected.

Applications can choose their own Zigbee partition layout by setting
`BMX_ESP32_ZIGBEE_PARTITIONS` to an **absolute path** before invoking bmk. The
table must include `zb_storage` with type `data` and subtype `nvs`; it may
resize the OTA and application storage regions. bmk selects a separate
sdkconfig variant keyed to the table's contents, so changing that table does
not reuse stale Zigbee partition settings.

## Hardware test

The diagnostic `examples/zigbee_sdk_probe.bmx` configures the Waveshare H2 as a
coordinator/on-off light on channel 15 and the XIAO C6 as an end-device/on-off
switch. The H2 forms and opens the network. The C6 joins, discovers the light,
binds its on/off cluster, and sends a toggle every ten seconds. It then requests
a read of the light's on/off attribute. Radio callbacks stay in native code;
no BlitzMax objects are passed to them.

Build and flash one board at a time, setting `ESPPORT` to its verified port:

```sh
ESPPORT=/dev/cu.usbmodem1401 bmk makeapp -a -r -x -l esp32 -g riscv32 -board waveshare_h2_dev_kit_n4 examples/zigbee_sdk_probe.bmx
ESPPORT=/dev/cu.usbmodem1101 bmk makeapp -a -r -x -l esp32 -g riscv32 -board xiao_esp32c6 examples/zigbee_sdk_probe.bmx
```

The H2 profile requires a manual RESET after flashing. Allow up to 60 seconds
for the C6 to join and bind. Expected serial messages include `Startup
status=0`, `Commissioning`, `Binding light`, `Switch binding complete`,
`Toggle request result=0`, `Light On/Off=`, and `Read light On/Off=`. Reboot
both boards and check `factory_new=0` and subsequent toggles. The probe never
erases Zigbee state; a deliberate factory reset API will be added before this
becomes a production module.

With both probes running, the bounded serial regression test is:

```sh
python tests/zigbee_pair.py --h2 /dev/cu.usbmodem1401 --c6 /dev/cu.usbmodem1101 --timeout 70
```

It prints both serial streams and passes after it sees both light states, a
successful toggle request, and a read-back response. It fails clearly on a
serial error or timeout.

## Verified on 17 November 2026

- `bmk` built the pinned v2.1.0 component with ESP-IDF 6.1 for both H2 and C6.
- Both images flashed. The H2 received repeated on/off toggles from the C6.
- After resetting the H2, it reported `factory_new=0` and continued receiving
  toggles, showing that its network state survived the reboot.
- A normal H2 `hello_world.bmx` build retained its board partition table and
  did not include the Zigbee component.
- An absolute-path custom Zigbee partition table built successfully.
- The C6 USB console stopped accepting the flash tool after a later serial
  reset sequence, while the C6 continued transmitting Zigbee toggles. A manual
  RESET restored the port. The updated C6 image then flashed successfully.
- The two-board regression test passed after the reset: C6 logged successful
  toggle and read requests, H2 logged both On/Off states, and C6 read back
  `On/Off=1`. The test completed in about 20 seconds with a 55-second timeout.

The bring-up source is adapted from Espressif's current

examples. See the [ESP Zigbee SDK](https://github.com/espressif/esp-zigbee-sdk)
